### 关键判断（以后别踩）

**GitHub Actions 只能定时执行，不能接收 HTTP 请求**，所以 `push-server` 里的 `/api/subscribe`

其他坑：cron 是 UTC；仓库 60 天无提交会自动停用定时任务；只对默认分支生效；
public 仓库会公开 subscribers.json 里的 openid，建议设 private。

## 用户反馈「内容停在 10.17 不更新」

### 根因

不是不更新，是**真机请求源站失败后回退到了包内快照**，而快照是生成那天（10-18 抓的 10-17 数据）的静态文件。
真机/体验版会校验 request 合法域名，`api.cntv.cn` 没配进小程序后台，所以拿到的是快照。

排查手法：直接 curl 源站确认最新是 10-18，再看 `data/snapshot.js` 的 `[0].date` 是 10-17 —— 两边一对比就能定位。

### 修复

- 重新抓取并生成快照，最新到 10-18（30 条要点）
- 首页在 `degraded` 时显示「存档」标记 + 明确文案「当前是 X月X日 的存档」
- **设置页新增「检测数据源连接」**：直接 `wx.request` 源站，
  失败时若 `errMsg` 含 `domain list` 就明确提示去配 request 合法域名
- 版本 1.0.1 已通过 CLI 编译（296.5 KB）并上传
- 已 commit `28bc76c` 并推送到远程

### 结论（重要）

数据源直连模式下，**必须在小程序后台配置 request 合法域名**，否则永远只会显示包内快照。
路径：开发管理 → 开发设置 → 服务器域名 → request 合法域名 → 添加 `https://api.cntv.cn`

## 新增「点开看详细内容」（v1.1.0）

### 数据源突破

同一个接口 `api.cntv.cn/NewVideo/getVideoListByColumn` 换 `mode` 参数拿到两种数据：

- `mode=0` → 每期「本期节目主要内容」清单（原有）
- `mode=1` → **每期拆开的单条视频列表**，含 `[视频]标题` + time + 单条页面 URL（新发现）

单条页面（`tv.cctv.com/2026/10/18/VIDExxx.shtml`）里 `#content_area` 就是**完整文字稿**，
形如 `<div class="content_area" id="content_area"><p>央视网消息（新闻联播）：…</p>…</div>`。

`mode=1` 单页 `n=100` 约覆盖 8 天，`n=20` 覆盖 2 天。

### 实现

- `utils/source.js`：并发抓 mode=0（结构）+ mode=1（分条地址），按「日期 + 归一化标题」挂到条目上
- `utils/article.js`：抓单条页面 → 解析 `#content_area` 的 `<p>` → 解 HTML 实体 → 按条目缓存
- `pages/brief`：新详情页，展示正文段落；快讯组先列子项再显示正文
- 首页与往期详情页的条目都改成可点击
- 匹配率 **252/252**（超长标题用前缀匹配兜底，阈值 12 字符）
- 版本 1.1.0 已上传（326.1 KB），commit `b7f52b6` 已推送

### 运维要点

**现在需要配两个域名**：`https://api.cntv.cn` 和 `https://tv.cctv.com`。
真机上开发版/体验版打开「调试模式」可临时跳过域名校验。

覆盖范围：分条地址抓 2 页（约 16 天），更早的期次点开显示「暂无文字稿」。
