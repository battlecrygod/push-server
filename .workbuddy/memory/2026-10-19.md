## 昨日联播：补充 GitHub Actions 定时推送方案

用户问 Actions 怎么定时跑，这次把这条路补完整。

### 改动

- `push-server/src/config.js`：配置来源改为 **环境变量 > config.json > 默认值**。
  支持 `XWLB_APP_ID` / `XWLB_APP_SECRET` / `XWLB_TEMPLATE_ID` / `XWLB_CLIENT_TOKEN` /
  `XWLB_PAGE` / `XWLB_MINIPROGRAM_STATE`。config.json 缺失不再直接抛错（只要有环境变量）。
- `push-server/src/index.js`：补上 `--once`（跑一次就退出，任何失败返回非 0 退出码）。
  之前 README 提到了 `--once` 但代码没实现，是个文档与实现不一致的 bug。
- `.github/workflows/daily-push.yml`：每天 UTC 23:30（北京 07:30）跑一次，支持 workflow_dispatch 手动触发，
  `permissions: contents: write` 用于提交订阅名单。
- `push-server/GITHUB-ACTIONS.md`：完整操作文档 + 坑位说明。
- `.gitignore`：排除 config.json / token.json / state.json / node_modules，**但保留 miniprogram_npm**
  （那是内置的云 SDK，不提交会导致克隆后跑不起来）。

### 关键判断（以后别踩）

**GitHub Actions 只能定时执行，不能接收 HTTP 请求**，所以 `push-server` 里的 `/api/subscribe`
在 Actions 模式下用不了——「收集订阅名单」必须另配常驻端点（Cloudflare Worker / 云服务器），
或者手动把 openid 写进 `data/subscribers.json`。这条已写进文档第 5 节。

其他坑：cron 是 UTC；仓库 60 天无提交会自动停用定时任务；只对默认分支生效；
public 仓库会公开 subscribers.json 里的 openid，建议设 private。
